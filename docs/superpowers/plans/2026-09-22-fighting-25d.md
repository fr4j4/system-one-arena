# Fighting 2.5D implementation plan

Scope authorized: original 3D fighters rendered with Three.js, authoritative movement restricted to the XY combat plane, rounds/powers and separately selected model providers for P1/P2 in the same match.

1. Deterministic fighting world: resource costs, windup/recovery, guard, jump, projectiles, special attack, bounded best-of rounds and scoreboard. Original Ember/Flux fighters; no external assets.
2. Dedicated battle coordinator: independent provider loops and perspective per slot, common simulation, player-tagged telemetry, round freshness checks, immediate shared pause/stop. Shared provider capacity remains respected.
3. Three.js renderer: procedural articulated characters, side camera, lit arena, action/impact animation, power projectiles, HUD and WebGL fallback. Dispose GPU resources and lazy-load the view.
4. Slot/round controls and per-player inspector. Disable two-independent-run A/B for fighting; preserve it elsewhere. Persist and replay battle states.
5. Physics/round/routing/pause/stop tests, browser slot/3D checks, visual inspection, build/lint, isolated real provider smoke, docs and push. Do not interrupt user simulations during isolated tests.

Completed: all five steps. Verification: 100 backend tests, 11 browser tests, TypeScript/Vite build, Ruff and Prettier. Real Jev-vs-reference smoke applied decisions for both slots; details in docs/verification.md.
